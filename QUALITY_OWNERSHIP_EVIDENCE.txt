RÈGLES
======

1. Le même rôle peut être simulé par la même équipe/agent, mais la revue doit rester séparée.
2. Une preuve d'un ancien SHA ne certifie pas automatiquement un nouveau SHA.
3. Une modification documentaire seule nécessite Build Validation mais ne remplace pas les preuves device existantes.
4. Une modification visuelle invalide les captures visuelles concernées.
5. Une modification de mouvement/caméra invalide la certification confort correspondante.
6. Une modification data invalide les tests persistence correspondants.
7. Une modification social/invite/share invalide les tests sociaux concernés.
8. Un infra timeout/429 n'efface pas les specs passées, mais le gate reste ouvert jusqu'à un run vert.
9. Toute réserve doit devenir une issue/backlog explicite avant release.
10. Aucun champ critique vide lors du release freeze.
