CHAOS SURVIVAL — MANUEL DE REVUE MULTI-EXPERTS PREMIUM
=======================================================

MISSION
-------
Chaque aspect du jeu doit être évalué comme s'il avait un responsable senior spécialisé.
Une feature n'est pas "premium" parce qu'elle fonctionne. Elle est premium lorsqu'elle :
1. remplit son objectif joueur ;
2. est cohérente avec toutes les autres disciplines ;
3. reste excellente sur Android ;
4. reste lisible sous pression ;
5. résiste à une session longue ;
6. possède des preuves de validation ;
7. ne crée pas de dette cachée.

Ce document complète :
- EXPERIENCE_MASTER_PLAN.md
- GAME_FEEL_UX_GUIDE.txt
- AAA_VISUALS_ANIMATION_GUIDE.txt
- VISUAL_OVERHAUL_PLAN.txt
- RELEASE_CHECKLIST.md

RÈGLE DE GOUVERNANCE
--------------------
Pour toute modification importante, simuler les revues spécialisées ci-dessous.
Chaque expert rend :
- PASS ;
- PASS AVEC RÉSERVE ;
- FAIL ;
- NON TESTÉ.

"NON TESTÉ" n'est jamais équivalent à PASS.
Une version ne peut pas être déclarée finale si un P0/P1 est FAIL ou NON TESTÉ.

======================================================================
01 — DIRECTEUR CRÉATIF / CREATIVE DIRECTOR
======================================================================

Question centrale :
"Le jeu a-t-il une identité immédiatement reconnaissable et une promesse cohérente ?"

Vérifie :
- fantasy centrale : survivre ensemble à un chaos spectaculaire ;
- cohérence sci-fi / broadcast / compétition ;
- identité propre des quatre arènes ;
- ton des textes, sons, couleurs, récompenses ;
- absence de features contradictoires ;
- qualité perçue dès les 30 premières secondes ;
- cohérence entre jeu, icon, thumbnails, trailer et store page.

Refuse :
- feature tendance sans rapport avec la fantasy ;
- mélange de styles visuels arbitraires ;
- surcharge méta qui dilue la survie ;
- copie évidente d'un autre jeu.

Preuves :
- capture première minute ;
- planches de quatre arènes ;
- capture lobby/READY/ROUND/RESULT ;
- phrase de pitch compréhensible sans explication.

======================================================================
02 — GAME DIRECTOR
======================================================================

Question :
"Chaque système renforce-t-il la boucle principale ?"

Vérifie :
- vote -> anticipation -> survie -> résultat -> revanche ;
- temps mort ;
- variété réelle des catastrophes ;
- agency ;
- tension ;
- Final Rush ;
- Double Chaos ;
- progression sans détourner du gameplay.

Mesures :
- délai join -> première action ;
- délai join -> premier round ;
- durée moyenne d'intermission ;
- nombre de décisions significatives par round ;
- taux de second round.

======================================================================
03 — LEAD GAME DESIGNER
======================================================================

Question :
"Les règles créent-elles des décisions intéressantes et apprenables ?"

Vérifie chaque catastrophe :
- télégraphe ;
- fenêtre de réaction ;
- contre-jeu ;
- récupération après petite erreur ;
- skill ceiling ;
- interaction avec map ;
- interaction Double Chaos ;
- solo vs multi.

Refuse :
- RNG sans contre-jeu ;
- safe spot permanent ;
- combinaison impossible ;
- règle uniquement expliquée par texte.

======================================================================
04 — LEVEL DESIGNER
======================================================================

Question :
"Le joueur lit-il l'espace et prend-il des routes intéressantes ?"

Pour chaque map :
- spawn lisible ;
- centre identifiable ;
- 2+ choix de route ;
- verticalité utile ;
- pads utiles ;
- lignes de vue ;
- refuge temporaire mais pas permanent ;
- landmarks ;
- pas de cul-de-sac injuste ;
- hazards compatibles avec topologie.

Test :
- capture depuis chaque spawn ;
- parcours sans HUD ;
- Meteor/Bomb/Lava/Shrink/Freeze/Double Chaos.

13 — GAME FEEL DESIGNER

======================================================================
17 — COGNITIVE / HUMAN FACTORS SPECIALIST
======================================================================

Question :
"Combien d'informations concurrentes le cerveau doit-il traiter ?"

ROUND :
3 éléments saillants maximum.

Cherche :
- change blindness ;
- inattentional blindness ;
- surcharge ;
- conflit couleur ;
- texte trop long ;
- choix trop nombreux ;
- feedback simultanés.

Final Rush :
supprimer davantage de méta au lieu d'ajouter davantage de spectacle.

======================================================================

"Les joueurs ont-ils de vraies raisons de se sentir ensemble ?"

======================================================================
21 — MONETIZATION / ETHICAL DESIGN REVIEW
======================================================================

Principe :
payer = expression, identité, confort raisonnable.
Jamais avantage compétitif.

Vérifie :
- pas de P2W ;
- prix compréhensible ;
- ownership restauré ;
- pas de popup après défaite ;
- pas de pression artificielle ;
- pas de faux rabais ;
- achats persistants.

======================================================================
22 — RETENTION / LIVE-OPS DESIGNER
======================================================================

Question :

======================================================================
23 — DATA / PRODUCT ANALYST
======================================================================

Funnel minimum :
join -> loaded -> vote -> ready -> round -> result -> second round -> 10 min.

Segmenter :
- nouveau/ancien ;
- solo/multi ;
- mobile/desktop ;
- Low/Medium/High ;
- survie/défaite ;
- ami présent/non.

Chercher les ruptures, pas seulement les moyennes.

29 — RELEASE MANAGER
======================================================================

Une release exige sur la même lignée :
- Build Validation ;
- Open Cloud ;
- Studio E2E ;
- Android ;
- desktop ;
- persistence ;
- alpha ;
- rollback.

Distinguer :
CODE FAILURE
vs
INFRA FAILURE.

Open Cloud timeout/429 après specs vertes = infrastructure externe.
Ne jamais masquer le rouge ; documenter et relancer.

======================================================================
33 — FRESH-EYES REVIEWER
======================================================================

Rôle volontairement non spécialiste.

Consigne :
jouer sans lire la documentation.

Noter uniquement :
- ce qui est confus ;
- ce qui semble cheap ;
- ce qui surprend positivement ;
- ce qui paraît lent ;
- ce qui paraît injuste ;
- ce qui donne envie de partager.

Ce rôle évite qu'une équipe experte devienne aveugle à ses propres habitudes.

======================================================================

Mission :
essayer de casser l'expérience.

Tester :
- ne jamais voter ;
- spam boutons ;
- rejoindre en plein round ;
- quitter pendant sauvegarde ;
- mourir immédiatement ;
- rester AFK ;
- réseau lent ;
- VFX Low ;
- son 0 ;
- ReduceMotion ;
- écran très petit ;
- solo ;
- serveur plein ;
- Double Chaos difficile.

======================================================================
35 — HARMONIZATION DIRECTOR
======================================================================

Intervient quand les disciplines sont individuellement bonnes.

Question :
"Le tout est-il meilleur que la somme des parties ?"

Cherche les conflits :
- VFX premium vs lisibilité ;
- animation premium vs contrôle ;
- décor premium vs performance ;
- progression riche vs charge cognitive ;
- social vs interruption ;
- audio riche vs warning ;
- AI réaliste vs fairness ;
- monetization vs confiance.

Peut demander de SUPPRIMER une feature pourtant bonne isolément.

======================================================================
PROCESSUS DE REVUE
======================================================================

ÉTAPE 1 — AUDIT VERTICAL
Un spécialiste examine sa discipline.

ÉTAPE 2 — AUDIT HORIZONTAL
Suivre une manche complète et observer les interactions entre disciplines.

ÉTAPE 3 — AUDIT CONTRADICTOIRE
Un second rôle cherche pourquoi la solution est mauvaise.

ÉTAPE 4 — DEVICE
Android + desktop.

ÉTAPE 5 — LONG SESSION
30–60 minutes.

ÉTAPE 6 — FRESH EYES
Joueur sans contexte.

ÉTAPE 7 — HARMONISATION
Retirer redondances, uniformiser timings, couleurs, sons, densité.

ÉTAPE 8 — RELEASE EVIDENCE
Associer chaque PASS au SHA et à une preuve.

======================================================================
DÉFINITION PREMIUM AAA-LIKE
======================================================================

Le projet peut viser la mention "premium AAA-like dans Roblox" seulement si :
- aucun P0 FAIL/NON TESTÉ ;
- aucun P1 FAIL ;
- les quatre arènes ont une identité propre ;
- les 11 catastrophes sont lisibles ;
- solo est amusant ;
- multi est meilleur que solo sans rendre solo incomplet ;
- Android reste fluide/lisible ;
- animation ne semble plus stock Roblox sur les moments clés ;
- audio ne semble plus générique sur les moments clés ;
- résultat donne envie de rejouer ;
- social reste volontaire ;
- économie reste équitable ;
- aucune feature critique ne dépend d'un seul canal sensoriel ;
- release checklist est entièrement prouvée.

"Parfait" signifie ici :
aucun défaut connu à fort impact + cohérence globale + preuves réelles.
Cela ne signifie jamais "plus aucune amélioration imaginable".
